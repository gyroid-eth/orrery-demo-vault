ORRERY のデモの流れです。上から順に進めます。各段の **確かめ** が見えたら次へ進みます。進めながら、[[タスク]] の板のカードにチェックを入れていくと、今日の Daily Note に「今日完了した」として並びます。

Windows の人は、コマンドを **WSL2 の Ubuntu の中**で打ちます（`user@PC:~$` のプロンプト）。Obsidian と PDF の変換は Windows 側で行います。

Windows Terminal から起動した agent や dashboard は、Ubuntu の窓を閉じても裏で動き続けます。使い終わって、WSL が使っているメモリを Windows に返したいときは、PowerShell で `wsl --shutdown` を打ちます（次に Ubuntu を開けば、また使えます）。

###### 0. この vault を開く

1. この vault のフォルダを置く。研究セット（下の 1）を実行した人は、すでに置かれています:
	- Mac: 例 `~/Documents/orrery-demo-vault`
	- Windows: 例 `C:\Users\<あなた>\Documents\orrery-demo-vault`（WSL からは `/mnt/c/Users/<あなた>/Documents/orrery-demo-vault`。`wslpath -u 'C:\Users\<あなた>\Documents\orrery-demo-vault'` で確かめられる）
2. Obsidian で「Open folder as vault」→ このフォルダを選ぶ
3. 「コミュニティプラグインを有効にしますか」と聞かれたら「Trust author and enable plugins」を押す

**この vault をそのまま開いてください。** Kanban のタスク板・Daily Note の一覧・論文の変換は、この vault に入っている plugin で動きます。中身を自分の vault に移して使うときは、先に次を済ませます（しないと、タスクのノートが Kanban にならず Markdown のまま出る、Daily Note の一覧が空になる、など）:

- コミュニティプラグインから入れて有効にする: **Kanban**・**Dataview**・**Templater**・**Calendar**・**QuickAdd**
- コミュニティプラグインに無いもの（**Task Done At**・**PDF Mistral (Hi-Res)**）: 自分の vault の `.obsidian/plugins/` に同じ名前のフォルダ（`task-done-at`・`pdf-mistral-plugin`）が**無いときだけ**、そのフォルダを作り、この vault の同じフォルダから **`main.js`・`manifest.json`・`styles.css`・`pdf.worker.min.js`（あるものだけ）** をコピーする。**`data.json` はコピーしない**（設定と API キーが入る場所。コピーすると自分の設定を上書きしうる）。Obsidian を開き直して有効にし、PDF Mistral の設定で **Markdown Output Folder** と **Images Output Folder** を `20_MDPapers`、**Images Folder Name** を `pdf-mistral-images`、**Image Render DPI** を `300` にする（この vault の手順と頼み方の文はこの置き場を前提にする。data.json をコピーしないと既定は vault の一番上）。キーは同じ画面で自分で入れる
- コマンドパレットの「**タスク追加**」（QuickAdd）を使うなら: `30_Templates/Scripts/addTaskQA.js` を同じ場所にコピーし、QuickAdd の設定で「Macro」の choice を「タスク追加」という名前で作り、その中に User Script として `30_Templates/Scripts/addTaskQA.js` を足し、⚡（コマンドに出す）を on にする。使わないなら、agent に `/addtodo` で頼めば足りる
- 設定: Templater の「Template folder location」を `30_Templates`、「Trigger Templater on new file creation」を on。コア機能の Daily notes の「New file location」を `02_DailyNotes`、「Template file location」を `30_Templates/Daily Note`。今日のノートを開いたときに作るなら「Files & links」→「Default file to open」を「Daily note」

**確かめ**: vault を開くと、今日の Daily Note が `02_DailyNotes/` に自動ででき（設定の「Files & links」→「Default file to open」が「Daily note」になっている）、「タスク」「今日完了した」「今日の作業ログ」の欄が並ぶ（別の日のノートは、左のカレンダーで日付を押す）。

###### 1. ORRERY を入れる

**README の 2 と 3 を済ませた人は、この段を飛ばして構いません。** お使いの PC の install の手順に沿って ORRERY を入れます。[Mac](https://github.com/gyroid-eth/orrery/blob/master/docs/install.md#mac) か [Windows 11](https://github.com/gyroid-eth/orrery/blob/master/docs/install.md#windows-11) です（Codex と Claude Code も入ります）。これで ORRERY 本体（agent の一覧・ORRERY Mail・cockpit）が入り、cockpit がブラウザで開きます。

次に研究セットを実行します（Mac はターミナル、Windows は WSL2 の Ubuntu の窓で）。

```bash
curl -fsSL https://raw.githubusercontent.com/gyroid-eth/orrery/master/scripts/research-set.sh | bash
```

研究セットは digest-paper の add-on を入れ、この vault が無ければ置き、**この vault を、これ以降に起動する agent の作業 folder にして**、最後に、Obsidian で開くフォルダと、agent に貼る頼み方の文（パスを埋めたもの）を出します。この vault をすでに置いた人にも、ノートは変えずに add-on だけを入れます。手で入れる手順は各 repository の README にあります。

Codex を使う人は、**研究セットの後に**[Codex の plugin を入れる](https://github.com/gyroid-eth/orrery/blob/master/docs/install.md#codex-の-plugin-を入れるcodex-を使う人)を行います（終了した Codex の agent を再開するのに必要です）。

**確かめ**: cockpit がブラウザで開き、研究セットの最後の要約に `work folder  the vault (…)` の行がある（この vault がこれ以降の agent の作業場所になった、という意味）。README で研究セットを済ませた人が再実行したときは `work folder  already the vault` と出ますが、それも成功です。agent はまだ起動していません。起動するのは 2 です。

###### 2. しりとりで通信を確かめる

研究セットの後に、cockpit の NEW AGENT から agent を起動します（既定でこの vault の中で動きます）。次を頼みます。

**agent は、この vault のフォルダで動かします。** この vault の `/addtodo`・`/adddone`・`/log` と決まりごと（`CLAUDE.md`・`AGENTS.md`）は、この vault で動く agent にだけ見えます。研究セットより前から動いていた agent は古い場所のままなので、いったん exit して起動し直してください。ターミナルで自分で agent を起動するなら、`cd <vault のパス>` → `codex`（または `claude`）です。別のフォルダ（`~/orrery` など）で起動すると、これらが出てきません。

> $delegate で子を 1 体起動して、Mail でしりとりを 3 往復してください

これは Codex の agent に頼む文です。Claude Code の agent には `$delegate` を `/delegate` に替えて頼みます（Codex では `/` から始まる語が Codex 自身のコマンドとして扱われるためです）。子は Codex でも Claude でも構いません。

**確かめ**: cockpit の右の Mail の欄に、二人の間の「しりとり」の Mail が流れる。mini-orrery に親子の線が出る。一巡もしないときは、ORRERY Telemetry のトラブルシューティングを見る。

###### 3. 論文の PDF を Markdown にする（pdf-mistral・やり方の案内）

ここは**やり方の案内**です。`20_MDPapers/` に、変換済みの論文 6 本（Onimaru et al. 2016 と、Tanaka et al. 2024・Inoue and Kondo 2016・Imada et al. 2025・Nojoomi et al. 2018・Seelinger et al. 2024。いずれも CC BY 4.0、[[論文の出典とライセンス]]）が同封されています。**同封の変換済みを使ってよい**ので、変換を試さずに 4 へ進めます。自分の論文を変換するときのやり方は次のとおりです（Mistral のキーが無い人も、4 で「PDF を local で変換してから」か「同封の変換済みから」を選べます）。

1. Obsidian の設定 → コミュニティプラグイン → **PDF Mistral (Hi-Res)** の設定で、Mistral の API キーを入れる。キーは Obsidian の設定の中だけに置き、チャットやノートに書かない
2. 試しに変換できる PDF は `10_Reference/Papers/` にある（Guo et al. 2024。[[論文の出典とライセンス]]）。同封の変換済みの Markdown は `20_MDPapers/`、digest-paper の見本のノートは `10_Reference/Notes/` の Onimaru et al. 2016 のもの。同じ場所の `=tanakaFabricSoftPneumatic2024=.md`（Tanaka et al. 2024）は、読書ノートの例（digest-paper の出力ではない）。自分の論文を使うときは、PDF をこの vault の中に入れる
3. PDF を開き、コマンドパレット（`Cmd+P` / `Ctrl+P`）で「Convert PDF to Markdown with images」を実行する

**確かめ**: `20_MDPapers/` に論文の Markdown が、`20_MDPapers/pdf-mistral-images/` に図ができる。

PDF は Mistral に送られます。未公表の論文や共同研究の資料は、所属先の条件に従ってください。

Mistral の無料プランでは、クレジットを使っていなくても 429（Too Many Requests）が出て、pdf-mistral が使えないことがあります。10 ドルのクレジットを追加すると解消します。クレジットを入れない場合は、4 の「PDF を local で変換してから」を使います。

###### 4. digest-paper で、agent のチームに読書ノートを作らせる

digest-paper は ORRERY の add-on です。書き手が下書きを作り、別の agent の確かめ役が本文と図に照らして確かめ、指摘を ORRERY Mail で直接やりとりします。Claude と Codex の両方があれば Claude が書き Codex が確かめ、片方だけなら同じ種類の agent 2 体で受け持ちます（そのときは、別の会社のモデルによる確かめではないと、ノートに書かれます）。

1. add-on は、1 の研究セットの 1 行で入っています
2. 研究セットの最後の画面に出た頼み方の文を、この vault で動く agent に貼る。3 つあります:
	- (a) pdf-mistral で変換した論文から
	- (b) **Mistral のキーが無いとき**: PDF をこの機械で変換してから（例: `10_Reference/Papers/` の Guo et al. 2024。PDF は外に送らない。図はキャプションごとの切り出しとページ全体の画像で、pdf-mistral より粗い。スキャンの PDF は不可）
	- (c) 同封の変換済みの 6 本（Onimaru と 5 本。`20_MDPapers/` にある）から選ぶ（一番速い）。研究セットが出す頼み方の (c) は Onimaru になっているので、他の 5 本にするときは、頼み方の「論文」の行を、選んだ `.md` のフルパス（`<vault のパス>/20_MDPapers/<論文名>.md`）に替える
	
	画面を閉じてしまったときは、次の形で頼む（パスは自分の環境のものに置き換える）:
	> digest-paper で、この論文のノートを作って。
	> 論文: `<vault のパス>/20_MDPapers/<論文名>.md`
	> vault: `<vault のパス>`、図のフォルダ: `<vault のパス>/20_MDPapers/pdf-mistral-images`
	> 保存先: `<vault のパス>/10_Reference/Notes`

この vault で動く agent は、最初の作業の前に、ORRERY Mail に自分を登録します（「agent の identity が無い」といった表示で一度止まったように見えることがあります）。登録が済めばそのまま進むので、待ってください。

保存先は、この vault の決まり（`CLAUDE.md`）どおり **`10_Reference/Notes`** にします。別のフォルダを指定すると、`/log` の agent や Daily Note からノートが見つけにくくなります。

**確かめ**: cockpit で、書き手と確かめ役の間を Mail が行き来する。終わると `10_Reference/Notes/<citekey>-<hash>/=<citekey>=.md`（例: `=GuoSelfregulatedReversalDeformation2024=.md`）ができ、末尾の「確かめの組」の行に、どの組で確かめたかが出る。Onimaru 2016 は見本のノートがすでにあるので、それを選ぶと自分のノートは `…-r2` として隣にでき、見本と見比べられる。Tanaka 2024 を選んだときは、別のフォルダに自分のノートができるので、例のノートと見比べられる。ノートの `review_status` が `checked` になる（`checked` は、確かめ役が確認した点について本文と図に合っていたという意味で、論文が正しいという保証ではない）。

詳しくは digest-paper の README（日本語は README.ja.md）を見てください。

###### 5. `/log` で作業ログを残す

Codex には言葉で頼みます（ログの形は、この vault の `AGENTS.md` にあります）。

> 作業ログを書いて: 論文ノートを作った

Claude Code なら `/log 論文ノートを作った` と打ちます。

**確かめ**: `05_Agents/LOG_<日時> 論文ノートを作った.md` ができ、今日の Daily Note の「今日の作業ログ」の欄に、そのログが自動で出る。

###### 6. Daily Note と Kanban で確かめる

- [[タスク]] の板で、終わったカードにチェックを入れる。完了時刻が付き、「完了（Done）」の列へ移る
- 今日の Daily Note の「今日完了した」に、チェックしたカードが並ぶ
- 新しくやりたいことは、自分で足すなら `Ctrl+P`（Mac は `Cmd+P`）で「**タスク追加**」を選ぶ。タスク名・期限・ボードを聞かれ、未着手の列にカードが入る
- agent に頼むなら「〇〇をタスクに追加して」（Claude Code なら「`/addtodo 〇〇`」でも）
- agent に「〇〇終わった」（Claude Code なら「`/adddone 〇〇`」）と言うと、そのカードが完了の列に移り、今日の Daily Note の「今日完了した」に出る

###### 困ったとき

- vault の中の決まりごと（ノートの書き方、ログの形）は `CLAUDE.md`（Codex は `AGENTS.md`）に書いてある。agent はこれを読んで動く
- ORRERY の不具合は、それぞれの GitHub repository の Issues へ
