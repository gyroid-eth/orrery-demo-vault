Biomatter Lab（2026-10-01）のデモの流れです。上から順に進めます。各段の **確かめ** が見えたら次へ進みます。進めながら、[[タスク]] の板のカードにチェックを入れていくと、今日の Daily Note に「今日完了した」として並びます。

Windows の人は、コマンドを **WSL2 の Ubuntu の中**で打ちます（`user@PC:~$` のプロンプト）。Obsidian と PDF の変換は Windows 側で行います。

Windows Terminal から起動した agent や dashboard は、Ubuntu の窓を閉じても裏で動き続けます。使い終わって、WSL が使っているメモリを Windows に返したいときは、PowerShell で `wsl --shutdown` を打ちます（次に Ubuntu を開けば、また使えます）。

###### 0. この vault を開く

1. この vault のフォルダを置く
	- Mac: 例 `~/Documents/orrery-demo-vault`
	- Windows: 例 `C:\Users\<あなた>\Documents\orrery-demo-vault`（WSL からは `/mnt/c/Users/<あなた>/Documents/orrery-demo-vault`。`wslpath -u 'C:\Users\<あなた>\Documents\orrery-demo-vault'` で確かめられる）
2. Obsidian で「Open folder as vault」→ このフォルダを選ぶ
3. 「コミュニティプラグインを有効にしますか」と聞かれたら「信頼する」を押す

**この vault をそのまま開いてください。** Kanban のタスク板・Daily Note の一覧・論文の変換は、この vault に入っている plugin で動きます。中身を自分の vault に移して使うときは、先に次を済ませます（しないと、タスクのノートが Kanban にならず Markdown のまま出る、Daily Note の一覧が空になる、など）:

- コミュニティプラグインから入れて有効にする: **Kanban**・**Dataview**・**Templater**・**Calendar**・**QuickAdd**
- コミュニティプラグインに無いもの（**Task Done At**・**PDF Mistral (Hi-Res)**）: 自分の vault の `.obsidian/plugins/` に同じ名前のフォルダ（`task-done-at`・`pdf-mistral-plugin`）が**無いときだけ**、そのフォルダを作り、この vault の同じフォルダから **`main.js`・`manifest.json`・`styles.css`・`pdf.worker.min.js`（あるものだけ）** をコピーする。**`data.json` はコピーしない**（設定と API キーが入る場所。コピーすると自分の設定を上書きしうる）。Obsidian を開き直して有効にし、PDF Mistral のキーは設定画面で自分で入れる
- コマンドパレットの「**タスク追加**」（QuickAdd）を使うなら: `30_Templates/Scripts/addTaskQA.js` を同じ場所にコピーし、QuickAdd の設定で「Macro」の choice を「タスク追加」という名前で作り、その中に User Script として `30_Templates/Scripts/addTaskQA.js` を足し、⚡（コマンドに出す）を on にする。使わないなら、agent に `/addtodo` で頼めば足りる
- 設定: Templater の「Template folder location」を `30_Templates`、「Trigger Templater on new file creation」を on。コア機能の Daily notes の「New file location」を `02_DailyNotes`、「Template file location」を `30_Templates/Daily Note`。今日のノートを開いたときに作るなら「Files & links」→「Default file to open」を「Daily note」

**確かめ**: vault を開くと、今日の Daily Note が `02_DailyNotes/` に自動ででき（設定の「Files & links」→「Default file to open」が「Daily note」になっている）、「タスク」「今日完了した」「今日の作業ログ」の欄が並ぶ（別の日のノートは、左のカレンダーで日付を押す）。

###### 1. ORRERY を入れる

Mac はターミナル、Windows は WSL2 の Ubuntu の中で、次の 2 行を順に打ちます。

```bash
curl -fsSL https://raw.githubusercontent.com/gyroid-eth/orrery/master/scripts/get.sh | bash
curl -fsSL https://raw.githubusercontent.com/gyroid-eth/orrery/master/scripts/research-set.sh | bash
```

1 行目は ORRERY 本体（agent の一覧・ORRERY Mail・cockpit）を入れ、cockpit をブラウザで開きます。2 行目（研究セット）は digest-paper の add-on を入れ、この vault が無ければ置き、最後に、Obsidian で開くフォルダと、agent に貼る頼み方の文（パスを埋めたもの）を出します。この vault をすでに置いた人にも、2 行目は vault を変えずに add-on だけを入れます。手で入れる手順は各 repository の README にあります。

**確かめ**: cockpit の左に、起動した agent の名前が並ぶ。

###### 2. しりとりで通信を確かめる

この vault のフォルダで Claude Code を起動し（`cd <vault のパス>` → `claude`。cockpit の NEW AGENT なら、作業フォルダに vault のパスを入れる）、次を頼みます。

**agent は必ず vault のフォルダで起動します。** この vault の `/addtodo`・`/adddone`・`/log` と決まりごと（`CLAUDE.md`・`AGENTS.md`）は、vault のフォルダで起動した agent にだけ見えます。別のフォルダ（`~/orrery` など）で起動すると、これらが出てきません。

> /delegate で子を 1 体起動して、Mail でしりとりを 3 往復してください

（Codex が無い人は、子も Claude で構いません）

**確かめ**: cockpit の右の Mail の欄に、二人の間の「しりとり」の Mail が流れる。mini-orrery に親子の線が出る。一巡もしないときは、ORRERY Telemetry のトラブルシューティングを見る。

###### 3. 論文の PDF を Markdown にする（pdf-mistral）

**Mistral のキーが無い人**はこの段を飛ばし、4 で「PDF を local で変換してから」か「変換済みの Onimaru 2016 から」を選びます。

1. Obsidian の設定 → コミュニティプラグイン → **PDF Mistral (Hi-Res)** の設定で、Mistral の API キーを入れる。キーは Obsidian の設定の中だけに置き、チャットやノートに書かない
2. 試しに使う論文は `10_Reference/Papers/` にある（[[論文の出典とライセンス]]）。その場で変換するのは Guo et al. 2024。Onimaru et al. 2016 は、変換済みの Markdown と読書ノートの見本が入っている。自分の論文を使うときは、PDF をこの vault の中に入れる
3. PDF を開き、コマンドパレット（`Cmd+P` / `Ctrl+P`）で「Convert PDF to Markdown with images」を実行する

**確かめ**: `20_MDPapers/` に論文の Markdown が、`20_MDPapers/pdf-mistral-images/` に図ができる。

PDF は Mistral に送られます。未公表の論文や共同研究の資料は、所属先の条件に従ってください。

###### 4. digest-paper で、agent のチームに読書ノートを作らせる

digest-paper は ORRERY の add-on です。書き手が下書きを作り、別の agent の確かめ役が本文と図に照らして確かめ、指摘を ORRERY Mail で直接やりとりします。Claude と Codex の両方があれば Claude が書き Codex が確かめ、片方だけなら同じ種類の agent 2 体で受け持ちます（そのときは、別の会社のモデルによる確かめではないと、ノートに書かれます）。

1. add-on は、1 の研究セットの 1 行で入っています
2. 研究セットの最後の画面に出た頼み方の文を、この vault で起動した agent に貼る。3 つあります:
	- (a) pdf-mistral で変換した論文から
	- (b) **Mistral のキーが無いとき**: PDF をこの機械で変換してから（例: `10_Reference/Papers/` の Guo et al. 2024。PDF は外に送らない。図はキャプションごとの切り出しとページ全体の画像で、pdf-mistral より粗い。スキャンの PDF は不可）
	- (c) 変換済みの Onimaru et al. 2016 から（一番速い）
	
	画面を閉じてしまったときは、次の形で頼む（パスは自分の環境のものに置き換える）:
	> digest-paper で、この論文のノートを作って。
	> 論文: `<vault のパス>/20_MDPapers/<論文名>.md`
	> vault: `<vault のパス>`、図のフォルダ: `<vault のパス>/20_MDPapers/pdf-mistral-images`
	> 保存先: `<vault のパス>/10_Reference/Notes`

この vault のフォルダで `claude` を起動すると、最初の作業の前に、agent が ORRERY Mail に自分を登録します（「agent の identity が無い」といった表示で一度止まったように見えることがあります）。登録が済めばそのまま進むので、待ってください。

保存先は、この vault の決まり（`CLAUDE.md`）どおり **`10_Reference/Notes`** にします。別のフォルダを指定すると、`/log` の agent や Daily Note からノートが見つけにくくなります。

**確かめ**: cockpit で、書き手と確かめ役の間を Mail が行き来する。終わると `10_Reference/Notes/<citekey>-<hash>/=<citekey>=.md`（例: `=GuoSelfregulatedReversalDeformation2024=.md`）ができ、末尾の「確かめの組」の行に、どの組で確かめたかが出る。Onimaru 2016 は見本のノートがすでにあるので、自分のノートは `…-r2` として隣にでき、見本と見比べられる。ノートの `review_status` が `checked` になる（`checked` は、確かめ役が確認した点について本文と図に合っていたという意味で、論文が正しいという保証ではない）。

詳しくは digest-paper の README（日本語は README.ja.md）を見てください。

###### 5. `/log` で作業ログを残す

Claude Code に次を打ちます。

> /log 論文ノートを作った

**確かめ**: `05_Agents/LOG_<日時> 論文ノートを作った.md` ができ、今日の Daily Note の「今日の作業ログ」の欄に、そのログが自動で出る。

###### 6. Daily Note と Kanban で確かめる

- [[タスク]] の板で、終わったカードにチェックを入れる。完了時刻が付き、「完了（Done）」の列へ移る
- 今日の Daily Note の「今日完了した」に、チェックしたカードが並ぶ
- 新しくやりたいことは、自分で足すなら `Ctrl+P`（Mac は `Cmd+P`）で「**タスク追加**」を選ぶ。タスク名・期限・ボードを聞かれ、未着手の列にカードが入る
- agent に頼むなら、Claude Code に「`/addtodo 〇〇`」（または「〇〇をタスクに追加して」）
- agent に「`/adddone 〇〇`」（または「〇〇終わった」）と言うと、そのカードが完了の列に移り、今日の Daily Note の「今日完了した」に出る

###### 困ったとき

- vault の中の決まりごと（ノートの書き方、ログの形）は `CLAUDE.md`（Codex は `AGENTS.md`）に書いてある。agent はこれを読んで動く
- ORRERY の不具合は、それぞれの GitHub repository の Issues へ
